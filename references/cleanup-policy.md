# 清理决策规则

## 可再生候选不等于自动删除

| 范围 | 建议及代价 | 执行限制 |
| --- | --- | --- |
| npm `_cacache` | 包下载缓存；删除后需重新下载，影响离线安装 | 没有 npm/npx 安装或构建任务时，可纳入逐项确认 |
| uv/pip 下载缓存 | 删除后下载/构建包；已有环境通常仍在，硬链接可能令释放量小于目录占用 | 不删除虚拟环境，不把整个 `.cache` 纳入清单 |
| Homebrew 下载缓存 | 以后安装可能需重新下载 bottle/源码 | 停止 brew 操作；区分清理下载缓存与卸载已装软件，禁止顺带 autoremove |
| SwiftPM 缓存 | 依赖和构建产物可重建，下一次构建可能较慢 | 停止 Xcode/Swift 构建；本地未发布依赖可能需进一步判断 |
| Xcode DerivedData | 索引和构建产物可重建 | 逐个子目录处理，不包含 Archives、签名材料、设备数据；先停止构建 |
| Gradle caches | 可能很大；依赖/转换/编译缓存重建耗时，离线构建会受影响 | 仅在项目任务/守护进程不再写入时确认；停止 daemon 自身也需在授权范围 |
| pnpm store | 优先用已安装版本的 `pnpm store prune` 清理未引用条目 | 命令可能只释放部分空间；不要默认删除整个 store；不自动安装 pnpm |
| 普通应用 `~/Library/Caches/<应用>` | 先确认是可再生数据，再考虑关闭该应用后清理 | 包含大型下载、模型、离线数据或用途不明的项目时保留；当前代理相关项目排除 |
| 日志 | 体积小时通常保留；诊断、开发日志可能有价值 | 初版助手仅报告，不自动删除；另行明确保留期和具体文件再规划 |

脚本白名单仅限定它“能够处理”的路径，不证明项目“应该清理”。扫描候选必须再经过上述判断和用户确认。

## 只报告或保留

- `Downloads`、桌面、文档和用户素材：只报告总占用，不把“很旧”或安装包后缀当作删除依据。
- `Application Support`、`Containers`、`Group Containers`、浏览器用户资料、邮件、Messages、照片图库：保存应用状态和用户数据，不属于普通缓存清单。
- `~/.codex`、`~/.dsh`、`~/.agents`、模型、`codex-runtimes`、Node/Python 等运行时：不得因隐藏目录或 cache 名称而删除。
- Cargo registry、Maven repository、Docker/虚拟机、模拟器：单独说明依赖、离线能力、镜像/卷/设备数据及重建代价；初版仅纳入盘点，不能把原始占用直接计为本次可释放空间。
- 系统缓存、系统日志、`/System`、`/Library`、APFS/Time Machine 快照：报告可见范围，不绕过系统权限或关闭 SIP，不利用本技能做系统维护。
- 废纸篓：只盘点；移动到废纸篓与清空废纸篓是不同操作，后者不能隐含在前者的确认中。

## 年龄、进程与测量

根目录 mtime 不能说明所有内容“多久未使用”。如需按时间筛选，查看相关文件元数据，注明 mtime 与 atime 不一定代表实际使用。不要为了获得 atime 读文件内容。

仅查看相关进程的可执行名称来识别运行情况；进程检查和指纹检查都不能保证未来不会产生并发写入。当前正在使用的目录应延后，不通过反复重试或停进程来凑成可执行计划。

使用 GiB（2³⁰ 字节）或明确的 GB（10⁹ 字节）；保持一致。`du` 盘点的是分配块，计划指纹统计与 `du` 的硬链接计数策略可能不同；APFS 共享块、快照和链接会影响实际回收，最终以可用空间前后变化为观测值，并说明同期其他写入的影响。
